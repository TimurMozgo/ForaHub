# Turret Forge в Game Hub

Игра встроена в полноэкранный слой хаба через iframe с того же домена. Кнопка «В хаб» ставит игру на паузу, записывает локальную копию, пытается завершить синхронизацию и возвращает в каталог. Новая вкладка не открывается. Картинка предоставлена пользователем; описание сохранено полностью.

## Персональные сохранения

Сейчас используется подтверждённый аккаунт Sites/ChatGPT. Telegram-бота пока нет, поэтому Telegram ID ещё не является идентификатором игрока. При создании бота потребуется отдельная проверка Telegram initData и явная привязка старого аккаунта к новому; автоматически связывать их по username или email нельзя.

- Сервер получает владельца только из проверенной платформой сессии, а не из тела запроса.
- Локальные ключи разделены по SHA-256 идентификатора аккаунта. Чужие сохранения не загружаются при смене аккаунта.
- В D1 для игрока хранится последняя копия, предыдущая копия, номер ревизии и идентификатор операции.
- Сохраняются кредиты, здоровье, волна, рекорд, уровни/расположение 12 турелей и звук.
- Автосохранение работает примерно каждые три секунды игрового времени и после значимых действий. Локальная запись немедленная; серверные запросы объединяются с задержкой 1,2 секунды и повторяются после ошибки.
- При возвращении текущая волна начинается заново: враги и снаряды не входят в формат сохранения.
- При недоступном сервере после авторизации можно продолжать с имеющейся локальной копией. Неподтверждённый статус виден в верхней панели. Для первого открытия/подтверждения аккаунта нужна сеть; полноценный офлайн-запуск всего сайта не реализован.
- Одновременный запуск в нескольких вкладках одного браузера блокируется Web Locks, где API поддерживается. Между устройствами действует compare-and-swap по серверной ревизии. Конфликт требует выбора игрока; локальная ветка сохраняется в ключе `:recovery`.
- Старое standalone-сохранение `turret-forge-v1` не импортируется автоматически: оно не привязано к аккаунту и на другом домене недоступно.
- Это сохранение игрового прогресса, не античит и не платёжный журнал. Покупки за реальные Stars и платные права должны проверяться отдельной серверной логикой.

## Обновление игры

1. Изменить файлы `public/games/turret-forge/`, сохранив интеграцию `save-client.mjs` и контракт `game.js`.
2. Для обычных изменений баланса/графики сохранить формат сохранений 2. Не менять ключи и не сбрасывать базу.
3. Выполнить `node scripts/bump-forge-version.mjs YYYY.MM.DD.N`. Команда обновляет манифест и версии URL кода, стилей и ассетов.
4. Выполнить проверки ниже и собрать/опубликовать весь хаб штатным Sites workflow.
5. При следующем запуске игры хаб запросит актуальную версию без кэширования и загрузит её внутри себя. Уже идущий бой не перезагружается.

При несовместимом изменении структуры сначала написать и проверить миграцию старых сохранений, сохраняя исходную копию и поддерживая переходную версию API для старых клиентов. Сейчас реализован формат 2 и отклонение несовместимых записей кодом 426; универсального преобразователя будущих форматов нет. Миграции базы только добавляются, уже применённые файлы не редактируются. Перед несовместимым релизом нужен отдельный экспорт базы и план отката.

## Проверки

```
node scripts/test-forge.mjs
node scripts/test-forge-client.mjs
node node_modules/typescript/bin/tsc --noEmit
```

Первый тест выполняет настоящие SQL-запросы маршрута в SQLite с тестовыми подтверждёнными сессиями: два аккаунта, анонимный запрос, чужой origin, повтор операции, устаревшая ревизия, валидация состояния и предыдущая копия. Второй проверяет реальный клиентский модуль с моделируемой сетью: покупку, восстановление, потерю ответа после успешной записи, более новую локальную правку и конфликт.

В браузере проверены карточка и описание, запуск внутри хаба, покупка третьей турели за 50 кредитов, пауза, возврат в каталог и восстановление 130 кредитов/трёх турелей. Существующая исходная папка игры не изменялась.

Приватный доступ хаба сохранён. Для массового запуска потребуется отдельно разрешить аудиторию и подключить Telegram-вход. Автоматическая резервная копия не обещает отсутствие любых потерь: при аварийном завершении до локальной записи могут потеряться последние секунды, а при удалении данных устройства до синхронизации — неподтверждённые изменения.
